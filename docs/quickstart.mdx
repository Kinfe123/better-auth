# Quickstart

This guide takes you from a fresh install to a working email/password sign-in flow. By the end you'll have an auth instance, a mounted route handler, and a client that can sign users up and in.

## 1. Install Better Auth

```bash
npm install better-auth
```

## 2. Create the auth instance

Create `lib/auth.ts` at your project root. This is the single source of truth for your auth configuration.

```ts
import { betterAuth } from "better-auth";

export const auth = betterAuth({
  database: {
    url: process.env.DATABASE_URL!,
  },
  emailAndPassword: {
    enabled: true,
  },
});
```

## 3. Set environment variables

```bash
DATABASE_URL=postgresql://user:password@localhost:5432/mydb
BETTER_AUTH_SECRET=your-secret-here
BETTER_AUTH_URL=http://localhost:3000
```

## 4. Generate the schema and migrate

```bash
npx better-auth migrate
```

This creates the `user`, `session`, `account`, and `verification` tables your auth instance needs.

## 5. Mount the route handler

For Next.js App Router, create `app/api/auth/[...all]/route.ts`:

```ts
import { auth } from "@/lib/auth";
import { toNextJsHandler } from "better-auth/next-js";

export const { GET, POST } = toNextJsHandler(auth);
```

For SvelteKit, add a `+server.ts` hook at `src/routes/api/auth/[...all]`:

```ts
import { auth } from "$lib/auth";
import { toSvelteKitHandler } from "better-auth/svelte-kit";

export const { GET, POST } = toSvelteKitHandler(auth);
```

## 6. Create the client

Create `lib/auth-client.ts` in your frontend code:

```ts
import { createAuthClient } from "better-auth/client";

export const authClient = createAuthClient({
  baseURL: process.env.NEXT_PUBLIC_AUTH_URL ?? "http://localhost:3000",
});
```

## 7. Sign up and sign in

Call `authClient.signUp.email` to create an account, then `authClient.signIn.email` to authenticate:

```ts
// Sign up
await authClient.signUp.email({
  email: "user@example.com",
  password: "supersecret",
  name: "Ada Lovelace",
});

// Sign in
await authClient.signIn.email({
  email: "user@example.com",
  password: "supersecret",
});
```

Both calls return the user and session objects on success. Errors are typed and available in the `error` field of the response.

## Next steps

You have a working auth setup. From here you can add social providers in [Authentication](/docs/authentication), or turn on additional capabilities via [Plugins](/docs/plugins). To use the CLI for schema management, see CLI Usage.
