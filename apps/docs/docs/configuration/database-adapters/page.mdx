# Database Adapters

The project detects or configures database adapters.
## What This Is
Database adapter docs explain how the product connects to the same persistence layer as the host auth system. They identify supported adapters, the expected provider names, and what needs to be migrated before the UI can read or write records safely.
## Why It Matters
Database Adapters matters because it is part of how Root turns repository behavior into a usable developer or operator workflow. This page gives readers the mental model first, then uses implementation evidence as supporting context.
## Core Concepts
- Prisma
- Drizzle
- SQLite
- Postgres
- MySQL
- schema detection
## Typical Workflow
1. Identify which adapter the host Better Auth project already uses.
2. Confirm that the product can load the adapter and database connection from the host configuration.
3. Run migrations or schema pushes before using features that require additional columns.
## Detailed Configuration Model
Database Adapters controls behavior rather than UI copy. The important questions are what decision this configuration helps a developer make, what happens when it is absent, and what runtime behavior changes when it is enabled. This page keeps the mental model ahead of the raw files that mention the setting.

For Root, configuration usually answers one of four questions: who can access the product, where it is mounted, how it talks to auth or database state, and what optional capabilities are enabled. Each setting is documented in relation to one of those questions.

## Decision Points
- Is the setting required for every installation, or only for a specific framework, adapter, or deployment mode?
- Does the setting affect security, persistence, presentation, event tracking, or developer convenience?
- What does a developer verify after changing it?

## Success Criteria
- Readers know when to configure this area and when they can ignore it.
- Readers understand the consequence of a wrong value.
- Readers can connect the setting to a visible product behavior or runtime integration.
